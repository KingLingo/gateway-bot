# Gateway Bot 全站 UI 重设计规格

日期：2026-08-09

状态：已完成视觉方向确认，等待规格评审

## 1. 决策摘要

本项目在不改变现有业务逻辑、API、权限、路由和功能开关的前提下，重设计 Sub2API 项目的全部用户界面，并将用户可见品牌统一为 `Gateway Bot`。

已确认的方向：

- 品牌名：`Gateway Bot`
- 产品定位：面向用户的 AI API 订阅服务
- 首页主标题：`让 AI 接入触手可及`
- 首页不刻意强调 ChatGPT 或 Claude，模型品牌只在支持范围和订阅详情中出现
- 视觉语言：沉浸式深色入口，非对称构图，全中文说明
- 用户中心：订阅优先，余额和充值相关信息降为次级
- 管理后台：保留全部管理能力，订阅运营和系统状态优先
- 升级方式：Gateway Bot 自定义分支自动构建，不让官方二进制直接覆盖自定义 UI

## 2. 目标

1. 移除所有用户可见的 Sub2API 品牌元素，包括名称、S 标志、默认副标题、开源项目式终端示意、GitHub 导向和侧栏版本徽标。
2. 将首页从通用 API 网关介绍改为 Gateway Bot 的 AI API 订阅入口。
3. 将普通用户的首要信息从余额改为当前订阅、周期、用量、到期时间和可用模型。
4. 为管理后台建立统一、可扫描的数据工作台，减少发光卡片和颜色噪声。
5. 保持所有现有功能、路由、权限、字段、配置开关和 API 合同不变。
6. 建立可持续的自定义构建与上游同步方式，避免官方自动更新覆盖 UI。

## 3. 非目标

- 不新增注册、支付、购买、订单或订阅后端能力。
- 不开启当前关闭的功能。页面是否可见继续由现有后台配置决定。
- 不修改 API 路径、请求体、响应体、数据库结构或鉴权方式。
- 不重新设计业务流程，不改变表单字段名称和顺序。
- 不移除任何现有管理能力。
- 不在本次工作中重命名 Go 模块、二进制名称或内部代码包。

## 4. 当前状态审计

### 4.1 线上

- 线上版本为 `v0.1.173`。
- 首页仍使用 Sub2API 名称、S 标志、英文副标题和开源项目终端示意。
- 首页采用深色网格、青色发光、三等分功能卡和多色模型卡，品牌表达较通用。
- 用户与管理首页以大量同权重统计卡为主，余额占据最高视觉优先级。
- 侧栏显示 Sub2API 名称和版本徽标。
- 公开配置当前关闭注册、在线购买和支付。该状态不在本项目中改变。

### 4.2 本地源码

- 本地仓库处于 `v0.1.106` 附近，比线上和上游落后。
- 本地仓库已有与本项目无关的后端和部署改动，不能重置或覆盖。
- 实现必须从线上实际版本建立隔离工作区，不在当前脏工作区上直接开发。

## 5. 设计解读

这是一个面向中文 AI 用户的订阅制 API 产品，不是传统开发者网关官网，也不是纯运营仪表盘。

设计参数：

- `DESIGN_VARIANCE: 8`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 6`

应用方式：

- 首页允许更高的不对称程度和沉浸式构图。
- 用户中心将不对称用于订阅重点区，数据列表保持稳定。
- 管理后台以扫描效率为第一目标，降低装饰性布局变化。
- 移动端全部收敛为单列，禁止危险重叠。

## 6. 参考来源

本设计使用 `awesome-design-md` 的结构规范，覆盖视觉氛围、颜色角色、字体层级、组件状态、布局原则、响应式行为和反例约束。

参考方向：

- Claude：吸收温和的编辑排版与陶土色识别，但陶土色只用于 Claude 模型身份。
- Linear：吸收工作台的信息层级、紧凑导航和状态清晰度。
- Vercel：吸收字体精度、黑白对比和开发者产品的克制感。
- taste-skill：执行审计优先、反模板化、真实视觉资产、双主题、减少动态效果和最终预检。

这些是设计参考，不复制任何品牌官网或聊天产品界面。

## 7. 品牌与语言

### 7.1 名称

- 用户可见名称统一为 `Gateway Bot`。
- `Gateway` 使用主文字色，`Bot` 使用品牌绿色。
- 后台配置的自定义站点名仍然可以覆盖默认值。
- 默认值、占位符、文档标题、登录页、邮件模板和错误页不得再回退到 `Sub2API`。

### 7.2 标志

- 移除现有 S 标志。
- 第一版使用定制文字标志 `Gateway Bot`，不创建复杂图形标志。
- 头像、favicon 和移动端紧凑标识使用简单的 `G` 字标。

### 7.3 中文规则

- 中文为默认界面语言。
- 中文界面中的说明、状态、操作和导航不得混入英文营销标签。
- `Gateway Bot`、`API`、`API Key`、模型名和必要协议名可以保留英文。
- 现有英文语言包继续保留，语言切换能力不删除。
- 不使用“拼车”作为公开文案。
- 不使用空泛口号、虚构价格、虚构额度或虚构性能数字。

### 8.2 浅色主题

| 角色 | 色值 | 用途 |
|---|---|---|
| 页面背景 | `#F5F3ED` | 暖灰画布 |
| 主表面 | `#FCFBF7` | 内容和表单 |
| 次表面 | `#F0EEE7` | 辅助分区 |
| 边界 | `#D8D5CC` | 分隔线和控件边框 |

| 次文字 | `#70736B` | 说明和元数据 |
| 品牌绿色 | `#1F6B4A` | 主操作和选中态 |
| Claude 陶土色 | `#C76D4E` | Claude 模型标识，仅此用途 |

语义状态色可以使用红、黄、绿，但只能表达真实状态，不能用作装饰。

### 8.3 字体

- 拉丁字母、数字和品牌：自托管 `Geist Variable`。
- 中文：自托管 `Noto Sans SC`，按实际字重和字符范围优化体积。
- 表格数字使用等宽数字特性 `font-variant-numeric: tabular-nums`。
- 页面主标题桌面端控制在两行内，不使用超出容器的视口缩放字号。
- 字间距为 `0`，不使用负字距。

### 8.4 形状与材质

- 按钮和输入框圆角：`4px`。
- 面板、弹窗和主要容器圆角：`6px`。
- 状态标签可以使用小圆角，不使用满圆胶囊作为默认控件。
- 阴影只用于弹窗、浮层和真正抬升的对象。
- 数据区域以边界、留白和表面层级组织，不给每个数据点单独套卡片。
- 不使用霓虹外发光、紫色 AI 渐变、装饰网格和多个彩色图标底板。

### 8.5 图标

- 全站使用一个图标家族。
- 实现时引入并统一使用 Phosphor Vue 图标，标准线宽保持一致。
- 模型品牌图标继续使用现有 `@lobehub/icons`。
- 不新增手写 SVG 路径。

### 8.6 动效

- 首页首屏使用一次有顺序的加载动效，说明视觉层级。
- 关键区块进入视口时使用轻量透明度和位移动效。
- 按钮和开关提供明确的按下反馈。
- 表格、表单和管理页不使用持续动画。
- 只动画 `transform` 和 `opacity`。
- 全部动效支持 `prefers-reduced-motion`，减少动态效果时立即显示最终状态。
- 不监听原生滚动事件，不使用 React 或 Vue 状态跟踪连续滚动值。

## 9. 首页设计

### 9.1 首屏

- 页面采用沉浸式深色主题，首屏接近完整视口，但底部必须露出下一段内容。
- 主标题：`让 AI 接入触手可及`
- 副文案：`订阅主流 AI API，统一管理密钥、用量与周期。接入从这里开始。`
- 主操作：`进入控制台`
- 次操作：`接入文档`，仅在后台配置了文档地址时出现。
- 首屏不出现 ChatGPT、Claude 或其他模型品牌名称。
- 登录状态继续决定主操作前往登录页还是控制台。

### 9.2 首屏视觉资产

实现阶段生成一张专用位图作为全幅背景：

- 深橄榄黑摄影棚中的抽象建筑入口或层叠通道。
- 材质为半透明玻璃、磨砂金属和柔和实体光。
- 绿色是主要视觉信号，陶土色只作为极小辅助细节。
- 不包含文字、Logo、人物、聊天气泡或产品界面。
- 桌面比例约 `16:10`，同时生成移动端重新构图版本。
- 文字直接覆盖在全幅画面上，通过稳定遮罩保证对比度，不把首屏放进卡片。

另生成两张支持区图像，用于“订阅到调用”和“统一管理”段落，避免纯文字页面。

### 9.3 页面结构

1. 沉浸式首屏。
2. 接入路径：`选择订阅`、`创建密钥`、`开始调用`，采用连续路径布局，不做三个等宽功能卡。
3. 订阅价值：周期、额度、状态和到期时间清楚可见。
4. 模型支持：位于页面中段，展示实际已支持平台，不进入首屏主叙事。
5. 稳定与可见性：会话保持、用量追踪和渠道状态。
6. 结尾操作：`从一个 API Key 开始`，复用 `进入控制台` 这一操作意图。

## 10. 应用框架

### 10.1 侧栏与顶部栏

- 保留现有路由和主要导航名称。
- 允许使用分组标题改善扫描，但不更改路由地址。
- 移除 Sub2API 名称、S 标志和版本徽标。
- 侧栏顶部显示 Gateway Bot 文字标志。
- 顶部栏保留公告、语言、主题和账户菜单。
- 桌面侧栏保持可折叠。
- 移动端使用抽屉式导航。用户中心可以提供最多四个高频入口的底部导航，管理后台不使用底部导航。

### 10.2 用户首页

视觉优先级：

1. 当前订阅：套餐名称、状态、周期、到期时间和本周期用量。
2. 常用操作：管理订阅、创建密钥、查看用量、兑换权益。
3. 使用概览：本周期用量、今日请求、API 密钥和可用模型。
4. 最近使用和渠道状态。
5. 账户资产：余额和充值相关能力保留，但降为次级区域。

订阅数据为空时显示明确空状态，并根据现有购买功能开关决定是否显示购买入口。

### 10.3 管理首页

视觉优先级：

1. 订阅运营：有效订阅、即将到期、周期用量。
2. 系统状态：渠道、账号池、代理和错误情况。
3. 使用概览：请求、Token、模型分布和响应时间。
4. 用户、余额、兑换码、优惠码和审计数据。

所有指标继续使用现有接口。没有可靠数据的指标不得虚构。

## 13. 数据流与业务保持

- Pinia store、Vue Router、API client 和现有 composable 继续使用。
- 页面容器负责调用现有 store 或 API。
- 展示组件通过 props 接收数据，通过 emits 发出操作。
- 不新增全局状态，除非现有主题或布局状态已经位于 app store。
- 功能开关继续来自公开设置和管理员设置。
- 订阅、余额、购买和注册的可见性继续由现有配置判断。

## 14. 响应式与可访问性

- 桌面布局目标宽度：`1280px` 到 `1600px`。
- 平板断点：`768px` 到 `1023px`。
- 手机断点：小于 `768px`。
- 首页非对称布局在手机上变为单列，主操作保持首屏可见。
- 表格在手机上使用明确的横向滚动容器，不压缩到不可读。
- 触控目标最小 `44px`。
- 正文对比度达到 WCAG AA，关键正文目标 AAA。
- 所有输入框有可见标签，错误文字位于字段下方。
- 所有图标按钮提供中文可访问名称和悬停提示。
- 键盘焦点使用统一高对比焦点环。
- 主题切换、侧栏展开、弹窗和菜单均支持键盘操作。

## 15. 自定义分支与自动构建

### 15.1 分支模型

- 以线上实际安装版本为基线建立 Gateway Bot 自定义分支。
- 原官方仓库作为 `upstream`。
- 使用当前已登录的 GitHub 账号创建或复用 fork，作为 `origin`。
- 主自定义分支命名为 `gateway-bot`。
- 本地开发使用独立 git worktree，不修改当前脏工作区。

### 15.2 上游同步

- 定时任务检测 upstream 新版本。
- 检测到新版本后创建同步分支和 Pull Request。
- 自动合并上游代码，但不自动发布到 zgo。
- 只有前端测试、类型检查、构建、后端测试和视觉回归通过后，才允许合并到 `gateway-bot`。

### 15.3 自定义构建

GitHub Actions 负责：

1. 安装前端依赖。
2. 执行 lint、类型检查和单元测试。
3. 构建前端并嵌入 Go 二进制。
4. 执行 Go 测试。
5. 构建 Linux amd64 二进制。
6. 生成 SHA256 校验文件。
7. 发布 Gateway Bot 自定义 release。

发布标签格式：`gateway-bot-v<upstream-version>-r<revision>`。

### 15.4 zgo 更新

- 修改现有更新脚本，使其只跟踪 Gateway Bot 自定义 release。
- 保留当前的数据库备份、二进制备份、SHA256 校验、健康检查和失败回滚。
- zgo 不在本机编译，避免低内存实例因构建失败。
- 未发布自定义 release 时，线上不自动追随官方版本。

### 16.2 浏览器验证

使用 Playwright 验证：

- 桌面 `1440x900`、小型桌面 `1280x720`、平板 `768x1024`、手机 `390x844`。

- 侧栏、弹窗、表格、表单、菜单和主题切换。
- 无横向溢出、无文本遮挡、无按钮换行、无控制台错误。
- 首页英雄图真实加载，移动端构图正确，下一段内容在首屏底部可见。
- 减少动态效果时没有持续动画。

### 16.3 文案验收

- 中文界面不出现英文营销说明。
- 不出现“拼车”文案。
- 首页主标题准确为 `让 AI 接入触手可及`。
- 首页不在首屏强调 ChatGPT 或 Claude。
- 用户首页以订阅而非余额为第一信息。
- 不出现虚构价格、额度、性能或用户数量。

## 17. 发布与回滚

发布前：

1. 记录线上版本和配置。
2. 备份数据库和当前二进制。
3. 在本地或 CI 环境验证 release 校验和。
4. 更新公开站点配置为 Gateway Bot 名称、副标题和新 Logo。

发布时：

1. 安装自定义二进制。
2. 重启服务。
3. 验证 `/health`。
4. 验证首页、登录页、用户页和管理页。
5. 检查错误日志和静态资源加载。

失败时：

- 使用现有更新脚本恢复上一份二进制。
- 只有数据库迁移导致不兼容时才执行数据库恢复。
- UI 发布不应包含数据库迁移，因此正常回滚只替换二进制。

## 18. 风险与处理

### 上游冲突

上游经常修改前端。通过同步 Pull Request、组件级改造和视觉回归降低冲突风险。

### 自定义品牌被默认配置覆盖

同时修改前端默认值和线上公开设置，并为覆盖优先级添加测试。

### 首页表现力影响可读性

首屏使用固定内容宽度和遮罩，移动端取消重叠，所有文字通过对比度检查。

### 后台视觉过度影响效率

沉浸式构图只用于首页和订阅重点区。表格、筛选、表单和配置页保持稳定网格。

### 自定义版本落后上游安全更新

定时检测 upstream，安全更新可以走加急同步，但仍需完成自动测试和最小视觉冒烟后发布。

## 19. 完成标准

- 全部现有 UI 页面和共用组件使用 Gateway Bot 设计系统。
- 用户可见界面不再出现 Sub2API 品牌元素。
- 首页、用户中心和管理后台符合已确认的视觉与信息层级。
- 所有现有功能和路由正常工作。
- 桌面、平板和手机无明显布局问题。
- 深色、浅色和减少动态效果均通过验证。
- 自定义分支能够自动构建可部署 release。
- zgo 成功部署自定义 release，并保留可验证的回滚路径。
