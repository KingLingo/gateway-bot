# Gateway Bot Apple Glass 品牌与界面深化规格

日期：2026-08-10

状态：用户已授权自动推进

## 1. 目标

在保留现有路由、权限、API、字段、功能开关和后端兼容能力的前提下，将 Gateway Bot 深化为中文优先的 AI API 订阅产品。界面应具有苹果式产品编辑感、克制的 iOS 玻璃材质、原创品牌标记和更自然的不对称排版。

本阶段面向用户只呈现 GPT 与 Claude。Gemini、Grok 不再作为可购买、可发现或可创建的新产品入口；页面用“更多模型敬请期待”承接未来扩展。为避免破坏现有数据，后台协议、数据库枚举和历史记录读取能力保留。

## 2. 设计方向

- `DESIGN_VARIANCE: 8`：公共页和订阅重点区使用明显的不对称构图。
- `MOTION_INTENSITY: 4`：只使用一次性进入、状态切换和按压反馈。
- `VISUAL_DENSITY: 6`：公共页舒展，用户中心适中，管理端保持高密度。
- 氛围：冷色银灰、深石墨、半透明材质和清晰边界，不使用紫色 AI 渐变。
- 排版：避免连续等宽三列、重复卡片墙和所有内容居中；标题、正文、数据和操作形成错落节奏。

## 3. 品牌系统

### 3.1 Logo 概念

原创标记由三层含义组成：

1. 两个错位门框代表 Gateway 的接入入口。
2. 中间连续路径代表请求被稳定路由到模型。
3. 单一状态点代表 Bot 的在线与可用状态。

标记必须在 16px favicon、36px 侧栏、登录页和首页导航中保持清晰。交付包含 `logo.svg`、可复用 Vue 品牌组件、纯标记和文字组合。不得保留旧 S 标记、Sub2API 标题或旧蓝色渐变。

### 3.2 图标

- 通用操作统一使用项目已有 `@phosphor-icons/vue`，默认 regular 线宽。
- 移除侧栏和常用流程中的手写 Heroicons SVG，统一图标尺寸与视觉重量。
- GPT 与 Claude 使用 `@lobehub/icons` 品牌图标。
- 图标按钮必须保留可访问名称和悬停提示。
- 玻璃图标底板只用于品牌、关键空状态和主订阅状态，不给每个导航图标套底板。

## 4. 字体与排版

字体链采用系统原生方案：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text",
"PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Segoe UI", sans-serif
```

- 不打包或远程加载受许可限制的 SF Pro 字体。
- 大标题使用更轻字重和宽松行高，不使用负字距。
- 正文控制在 58-68 个中文字符宽度以内。
- 数据继续使用等宽数字特性，代码和密钥使用等宽字体。
- 首页通过错位列线、跨栏标题和不等高内容建立节奏；后台表格保持严格对齐。

## 5. 色彩、圆角与玻璃

- 页面画布：冷银灰 `#F4F6F8`；深色画布：石墨黑 `#0B0D0F`。
- 表面：浅色 `rgba(255,255,255,.72)`；深色 `rgba(22,25,28,.74)`。
- 主文字：`#17191C` / `#F5F7F8`；次文字：`#66707A` / `#9DA6AE`。
- 品牌信号色保留苔绿，Claude 陶土色只用于模型身份。
- 面板最大圆角 8px，控件 6px，状态标签和开关轨道可使用满圆。
- 玻璃只用于导航、认证壳、订阅重点区、浮层和弹窗；数据表、筛选区和普通页面分区使用实色表面。
- 玻璃必须同时具备半透明背景、细边界、适量模糊和可靠文字对比；低性能或减少动态偏好下保持可读。

## 6. 页面改造

### 6.1 公共首页

- 保留主标题“让 AI 接入触手可及”。
- 首屏改为偏左下的跨栏标题与右侧接入路径视觉，避免中心对齐和等分布局。
- 模型区只展示 GPT、Claude 和一个“更多模型敬请期待”静态席位。
- 接入路径改为连续的三步轨道，不使用三个等宽卡片。
- 文案围绕订阅、密钥、用量和稳定接入，不突出具体聊天产品名称。

### 6.2 认证与公共流程

- 使用同一品牌组件、系统字体和玻璃认证壳。
- 登录、注册、找回、验证、重置、OAuth 回调、用量查询和 404 保持原业务状态。
- 移动端优先保证表单可读、键盘操作和 CTA 不被遮挡。

### 6.3 用户流程

- Dashboard、订阅、购买和密钥流程继续以订阅为第一优先级。
- 模型广场、可用渠道、套餐模型范围和密钥接入引导只主动呈现 GPT/Claude。
- Gemini/Grok 的新建与营销入口隐藏；历史数据若由 API 返回，仍允许管理员识别和处理，避免形成不可维护记录。
- 余额充值继续降级，不删除其后端能力或受功能开关控制的流程。

### 6.4 管理流程

- 管理端统一字体、导航、表单、表格、弹窗、状态和空态，不改字段和接口。
- 新建账号、渠道和模型的首选列表只提供 OpenAI/Anthropic；历史 Gemini/Grok 记录保留可见性，但不作为新增推荐。
- 订阅运营和系统状态维持最高信息优先级。

## 7. 质量门禁

- ESLint、TypeScript、Vitest、前端生产构建和 Go 全量测试全部通过。
- 公开与认证路由在 `1440x900`、`1024x768`、`390x844`、`360x800` 无横向溢出、坏图和重叠。
- 首页、登录、订阅、密钥、用量、模型广场与主要管理页进行截图复查。
- 用户可见页面不得出现 Sub2API、旧 Logo、Gemini 或 Grok 的主动产品入口。
- 发布使用新的不可变 `rN` 标签，生产健康检查失败自动回滚。
